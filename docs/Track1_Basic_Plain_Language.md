# PRD 4.2 Basic 白话版（会议速读）

对应 [PRD 4.2](Track1_Data_Assessment_and_PRD.md)，按 2026-09-26 团队会议决定更新。**用户只需选地块，不必先知道要建哪类住宅或多少套。**

## 现在要做的事

- **B1 找地块：** 地图点选或输入地块编号。地址若对应多块地，先让用户选定；没选定唯一地块就不出报告。
- **B3 地图与报告同步：** 地图高亮、地块详情和报告显示同一个地块编号。地址、面积等缺失时写“未知”。
- **B4 分区分类：** 参考[市府 Zoning Map](https://pittsburghpa.maps.arcgis.com/apps/instant/sidebar/index.html?appid=4bb79ea64bf848b3a0560e3856efeccb)，说清这块地属于哪些分区。该地图是**分区图**，不能凭它判断地是平的还是山坡，也不能在不知道建设方案时断言能建什么。
- **B5 地形分类：** 另用 25%+ 陡坡图层，显示“检测到重叠／未检测到／数据不足”、重叠面积或比例和日期。没有定义过的标准时，不给整块地武断贴“平地／山地”标签。
- **B6 有边界的等级：** 如果证据足够，可用绿／黄／红表达**已核查的地块约束**；缺关键证据时是灰色。颜色旁写依据、来源、规则版本。没有具体住宅方案，这不是某项目的完整 Development Ease Score。
- **B7 全部障碍：** 把所有已发现的障碍列出来，每项写事实、可能影响、找谁核查和来源。报告开头可以突出最优先的几项，但不能藏掉其余障碍；未知项另外列。
- **B8 可读说明：** AI 只能解释已核实的资料，不能自己编法规或改等级。AI 失败时用模板报告。
- **B9 来源和日期：** 关键结论显示来源、数据日期和适用范围；说明这只是早期初筛，需要人工复核。

## 这轮删掉或暂缓的事

- **B2 已从 Basic 删除：** 开发商在找地阶段可能不知道住宅类型或单位数；将来有明确方案再做用途规则判断。
- **B10 暂缓：** 四类角色的 UI 设计以后详细规划。
- **B11 收尾再做：** 真实地块、从输入到结果的可重复演示是最后的整体验收工作。
- **B12 暂缓：** 还没有合适财务数据，先不做财务资料或分析功能；现有报告也不能声称已评估财务。

**例子：** 输入一个地块编号，看到它跨哪些 zoning 分区、是否碰到 25%+ 陡坡、全部已发现障碍及未知项。等用户以后确定要建什么，再讨论该项目是否符合具体用途规则。
